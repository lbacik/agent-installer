# `HOME` redirection, not a target-root flag, for build-time installs

Container images that ship a reviewed skill bundle need to run the installer during the build and have the result work for the runtime user. `resolveTargetPaths` in `src/paths.ts` derives every managed path from `process.env.HOME`, so running the installer with `HOME` set to the runtime user's home directory installs directly under the final paths. `pnpm test:package` already relies on this: it redirects `HOME` so the packaging smoke test never touches the real store.

A `--target-root` flag was considered instead, so a build layer could install into a staging directory and copy the tree into the runtime image afterward. It was rejected: Claude exposure symlinks are created with an absolute target (`await fs.symlink(current.basePath, current.exposurePath)` in `src/install.ts`), so installing into a staging root and relocating the tree afterward produces symlinks that still point at the staging path and silently break exposure at runtime. A `--target-root` flag would invite exactly that broken workflow.

The decision is to document `HOME` redirection as the supported way to install at build time, and to not add a target-root flag. Install under the final runtime home directly, or reinstall after relocating; never relocate an installed tree. This is a documentation-only decision with no new CLI flag or behavior change: a build step must install under the runtime user's actual home path, and if a build ever needs to relocate an installed tree, the correct fix is to reinstall after the move, not to relax this constraint.
